# 《猫壳机动队》Windows 试玩交接

这个项目为 Claude Code 第五期选题收集实测材料。让 AI 只凭玩家可见的画面和普通键鼠试玩 Steam Demo，记录它独立走到哪里、学会哪些规则、能否复现问题，以及耗时、模型用量和人工帮助。

## 在 Windows 上从哪里接手

下一局统一按 [RSI 执行说明](RSI-RUNBOOK.md)记录，经验从 data/playtest.json 读取，网页和执行者使用同一份数据。下方旧经验表保留讨论依据。

下一局先用现场截图确认游戏版本、局号和当前页面，再按下文的[跨局经验表](#decision-memory)试玩。换电脑或换会话时也从这里接手。

在运行游戏的 Windows 电脑上，用 Codex 打开这个仓库，由 Steam 启动 Demo。接手会话可以直接执行下面这段任务。

> 定位游戏的实际渲染窗口。若从健康提示开始，点「继续」进大厅。右上齿轮打开菜单，点「设置」核对选项，「取消」回到菜单，再点「继续」回大厅。「开始游玩」进入挑战赛模式和机师选择。选人页的「开始」和「继续」分别对应新开和恢复，进入后核对天数、胜负、金币及装备栏。每一步用新截图确认变化，人工操作单列。

第二局爬塔已以12胜4负结束。后续若另开挑战赛，先读v0.5及第16天启动失败反例：盘库存→比较升级、购物、留息→重排五件装备并核对共享插槽→评估双方启动、成长、护盾和治疗→记录预测→战后三页核对→更新规则。此版本利息实测为每满5金币得1、最多10，有界面提示及多日结算支持。两局随机商店与对手不同，胜率变化不能当作单变量提升。

首次往返成功后，按首轮参考值补测：连续 20 次操作中至少 19 次达到预期，抽取 30 条文字中至少 27 条完整读对。然后从可重建的起点计时试玩十分钟，记录实际终点、决策数、动作成功数与总数、等待、人工介入及可得的 token。之后尝试跑完一局；发现疑似问题时，留下最短步骤、预期依据、实际结果和复现次数。

## 玩家讲过的基础玩法

以下规则来自玩家的试玩前说明，具体数值和触发条件留待游戏内核对。

| 游戏中的选择 | 已知玩法 | 第一次要看什么 |
|---|---|---|
| 升级或购买 | 每天先配置机甲。升级能提高血量及获得更好装备的概率；商店可以买装备和配件。 | 读出血量、等级、可用资源、升级费用和可买商品，比较这笔资源能立刻改善什么。 |
| 装备与插槽 | 五个装备区域各能穿一件。不同装备有不同属性和效果，移动装备可改变插槽位置及配件搭配。 | 用游戏原名记下五区装配。若位置可以还原，先挪动已有装备，观察手里的配件能否接上，再决定是否购买。 |
| 选对手与战斗 | 配置完成后可以查看其他玩家的装配。开战后配置固定。 | 记录按钮上显示的实际可用次数。本次第 1 天为两次免费重掷，记录保留或换对手的理由。 |
| 战后调整 | 结算能看到不同装配的伤害。 | 把伤害表对回战前配置，挑一处最值得调整的地方，带入下一天。 |

## 下一局怎样调用上一局的经验

每次决策都先确认当前状态、目标和可行选择，再取用相关经验。对候选选择回答同样四个问题：预期改善什么、付出什么代价、什么条件会失败、哪些关键输入仍未知。购物时可比较买入、升级和留钱，装配时可比较保留、换位和换装，选敌时可比较保留和重掷。观察说明或尝试可恢复操作，也可以作为先补信息的选择。

当试玩 AI 打开选敌、商店或装配页面，根据**当前画面**找到下表对应经验。条件吻合时，点击前把那一行的检查用于当前选择。看不清关键字段就查看说明或记为未知。没有匹配项时仍按上述四个问题决策，并把新发现记为待验证经验。以下来自版本 `1.0.0.2218`，换版时重新核对机制。

| 决策时机与可见条件 | 点击前做什么 | 经验的依据与状态 |
|---|---|---|
| 选敌时，对方有禁用效果，我方依赖主武器首次命中来启动成长或吸血 | 读对方控制节奏、我方主武器冷却和备用输出。回答“主武器第一轮被拖住，靠什么撑到首次有效攻击？”再根据剩余生命和重掷次数决定保留或换敌。 | 第二局第 16 天已察觉禁用风险，仍预测胜并保留对手。结算时己方伤害栏为空。控制对象和首击过程缺少完整记录。这条选敌方法待新局验证。[终局证据](playtest-2026-11-15-run02/tower.html#day16-result) |
| 购物时，准备给一件可能换下的武器买专属强化 | 先比较当前和候选武器，确定哪件出战，再决定是否买强化。记下支出和实际装上的武器。 | 第二局第 15 天花 16 金币给旧刀减冷却，当天改用新刀。可核对的是这 16 金币没有作用于当日出战武器。[当日购物记录](playtest-2026-11-15-run02/tower.html#day15) |
| 装配时，跨卡配件提示目标插槽无效，且卡序可恢复 | 先查左右端点是否同高，再试换一个邻位。看连线和两端属性，需要时恢复原位作对照。 | 第一局第 2 天，同一配件换邻位可重现失败和成功。可推广的范围仍取决于实际槽形与属性。[失败图](playtest-2026-11-15/day02-wrong-neighbor.jpg) · [成功图](playtest-2026-11-15/day02-aligned.jpg) |

**记录在当轮日志，每个匹配的决定一条。** 点击前写“局/日、现场图、当前倾向 → 调用了哪一行、补查到什么 → 最终动作、可核对的预期”。动作相同也写明理由。操作后在同一条追加“实际动作与结果、证据、支持／反例／看不清”。选敌时优先观察首次有效攻击；放弃的对手没有比赛结果，留空。新反例附回原行并缩小适用条件，旧证据保留。

**下一局结束后核对两件事。** ① 抽查战前截图，统计符合条件的决定有多少次，其中多少次在点击前用了经验，哪些是 AI 自己调用、哪些经玩家提醒。② 在有可见结果的决定中，核对预测和反例。要测经验本身的收益，另取未参与制定规则的局面，隐藏结算，在同一模型的两个新会话中分别只给战前资料、给相同资料加该条经验，比较两边的判断，再揭晓已打对手的结果。实战若整局没遇到某种条件，该行继续待测。

## 怎样记住经验并探索

- **本局快照**记录游戏日、等级、血量、资源、五区装配、插槽与配件、当前对手和重随机会。购买、换装或重随后更新变化的字段。中断时写下当前画面和下一个动作，恢复时用新截图核对。
- **每次决策**先写“我预期什么、为什么值得试”，再写实际结果和证据。优先尝试代价低、可还原、能影响眼前购买或装配的改动。战前图与伤害表用同一个游戏日编号。
- **跨局经验**记录适用条件，区分玩家说明、游戏文字、实机观察和策略假设。若两场的对手或时长不同，伤害差异只作线索，留待条件接近时复测。

每完成一项操作或优化，在当轮日志写下结果；优化还要记改前、改后和是否保留。阶段结束时更新本页的当前停点，让下一台电脑从最后一个有证据的画面继续。
