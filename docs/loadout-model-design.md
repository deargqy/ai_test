# 配件与装备联合建模 · 2026-11-17

用户要求：把全部可选配件、插槽和装备替换一起建模，离线排出多种布局再决定购买与装配。沿用已授权的流程优化，不另开 worktree、不提交、不操作暂停的游戏。

基线：第13天完整流程967.937秒，含讨论与记录；第14天在既定卡序上多次试拖，出现挤掉600%伤害桥、恢复后另试下排的往返。尚无可比较的优化后整日时间。

假设：先检查完整布局的约束、保留数个不同目标候选，能减少试拖与漏买。离线运行时间不是游戏日提速证明。

方案比较：继续人工局部替换遗漏全局组合；直接做完整战斗模拟缺少动画/随机充能/被动触发规则；采用可审计的插槽约束搜索，输出结构、费用和分项静态指标，再人工比较触发链。使用Python标准库及独立离线HTML。

数据：装备实例记录部位、阶级、主副属性、基础CD、被动文字、局部孔位、购买价、成长来源、截图；配件记录端点相对形状、占用线段、效果适用条件、拥有/在售、价格和截图。等级不自动生成孔位。所有孔位来自可见截图，遮挡或不确定项单列。

搜索：枚举每部位候选装备组合及5!卡序；配件搜索采用有界束搜索，保留进攻/防御/启动代理目标的候选，不能称全局最优。一个孔不能重复使用；同件两个端点只给一次属性收益；条件不符的端点仍占孔，但不算受益。采购不能超过现款，不预支未执行的出售。对桥身交叠分别运行保守不允许与端点不冲突即可两种假设。水平形状有证据，旋转未验证则不枚举。

评价：基础每次释放伤害（不含力量、坚固转伤、失盾成长、敌减伤）、每次盾、按各自CD的基础伤害率、每次坚固、主核CD、互充连接、被动文本和剩金。代理分仅用于缩小候选，不作为胜率或真实首击时间。需实战检验的候选统一标记未验证；拖动失败不自动转为几何不可能。

实现与验证：先写端点/跨度、占孔与交叠、同卡去重、预算及换装搜索测试；实现读取JSON→搜索→JSON+HTML；用第14天已有截图录入候选与当前基线；核验实际成功的旧连接可被模型表达，失败连接仍列待核；输出搜索规模、耗时与限制。暂停中的游戏配置不因离线模型改变。

验收：结果能画孔位和桥、指出每个端点的受益、列采购/未用配件/换装代价，包含换序和换装方案。恢复游戏后新图核状态，只按选定方案执行，并回填端点/数值与真实耗时。
