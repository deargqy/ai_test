顺序合理，补三处调整

先确定当天缺口。带着上场问题、已有库存和预算评价奖励与商品，避免从零分析所有流派。

购买前先做配件布局草案。买前算端点、属性和替换代价；买后集中装配验证，避免花完钱才发现布局不成立。

每轮新信息齐备后集中判断。商店刷新、奖励揭晓、换敌、装配失败都会改变可选项，在这些边界重新判断；同一轮不必每看一件物品都展开完整推理。

“配件可能比装备等级重要”作为构筑提示保留，不写成普遍排名。比较有效受益件数、触发频率、状态转伤、启动时间，以及换装损失的成长和连接。

一日流程：八个阶段，一条反馈循环

固定步骤：采集 / 执行模型判断：一组信息一次比较核实：结果与预期对照
  1. 1

    现场与当天目标

    新图确认阶段、天数、资源、等级与生命。读上日快照、库存和阶段经验；连续运行复用未变的信息。

    输出：当天状态 + 优先补强点
    画面 / 分辨率变了？重新定位；坐标只在已确认的布局中复用。
  2. 2

    事件：选装备 / 配件 / 科技，或拿钱

    收齐可选项，再比较核心联动与现金机会成本。科技按当前核心评估。没有选择的首领，完成必要配置后直接打。

    输出：事件选择 + 简短预测
    又揭示新选择？只补采新面板。首领跳过重随分支，战绩单独核对。
  3. 3

    是否升级，以及搜索预算

    比较生命、商店概率、金币与利息。升级不提高已有装备阶级。已生成的商品是否受升级影响，不能未经验证就假定。

    输出：升级 / 保留 + 搜索上限
    升级后核实金币、经验、生命与概率。保留“看到对手再补生命”的选择。
  4. 4

    扫描整店 → 一次购买判断

    整店图 + 需要的新说明，组成同一份商品观察表。结合库存与前次购买记忆，一次列购买清单、备选和刷新决定。

    集中采集 整店比较 购买核实
    刷新 ↺ 回到本步核预算再刷新。替换商品表，保留已买、放弃理由、缺口和预算余量。
  5. 5

    背包：整排布局、集中换装与清理

    先画候选连接，再移动装备和配件。核实连线、两端词条与数值。确认替换成功后再卖旧件，有明确用途的候选保留。

    深入判断 ①：配件整体收益
    装配失败？同方案最多两次不同尝试，换分支或恢复；保留失败预测。
  6. 6

    对手：打 / 重随 / 补生命

    集中读取关键装备、科技与配件。比较首次有效命中、前两轮触发、爆发、控制和续航。必要时补生命，再记录最终出战预测。

    深入判断 ②：完整触发链
    换敌 ↺ 重看敌方复用未变的我方信息；若当前界面不能升级，不把它列为可行选项。
  7. 7

    最快速度战斗，保留关键过程

    验证速度档。采集开场、首次有效攻击、关键启动和终场；战斗中不逐帧重新规划。采样密度先实测。

    过程采集
    采样遗漏？时间或剩血记未知，下场调整采样；不能用结算倒推没看到的过程。
  8. 8

    双方三页统计 → 一次复盘 → 次日

    合并伤害、防御、增益来源，先核胜负与资源，再检验原预测。选出下日最重要的一个改进点，批量保存结果和快照。

    回填证据 主要分析偏差
    ↺ 返回步骤1证据改变判断才修订经验。Bug独立归档，胜负预测失败不直接算Bug。

信息可以批量，变化必须分开

截图后的工具可以自行实现：接收本轮截图，按固定区域裁剪、编号、去重，打包后一次视觉识别，输出带原图来源的商品表（名称、等级、价格、属性、被动、槽位、未知字段）。不必先开发完整OCR系统；首版可以由工具整理图片、视觉模型整批读取，再做一次购买判断。识别和策略判断分开，低置信度字段才单独复查。

已实现：tools/observe.py打包截图，输出原图与hash、原尺寸裁剪、联系图、显式未知字段。视觉模型统一读图后可用annotate保存结构化结果。它不是自动OCR，也不操作游戏。23张敌详情采集24.914秒，排版1.72秒。剩余优化是减少重复分析、维护实例记忆和验证整日耗时。

实际采集边界

使用Computer Use与Steam F12；用户明确要求固定位置整组采集。只读详情批次逐项点击、刷新、截图，全部采完统一查看；批次中遇到输入变化即中止并重新观察。没有纯悬停API，不另造输入通道。购买、换装、选敌及出战不套只读批次。

固定点必须来自当前分辨率和布局。装备可能换序，所以采集编号按位置，部位由文字识别。缺详情、遮挡或过期才补拍。

模型主要深入判断这两处

① 配件：整排比较，而非逐件追等级

比较有效受益装备、实际加成、触发频率；扣除丢失的连接、被动、成长和经济。这是比较框架，不是已校准的伤害公式。

顺序：库存 → 装备顺序 → 实例槽位 → 配件跨度 → 两端属性 → 启动与循环 → 替换代价。

同件两孔只算一件；跨两件但一端没有有效输出，也不能算两份伤害收益。

RSI要求不减，减少重复抄写

一条记录对应一个有取舍的决定，可以覆盖同一观察下的一组购买或整排装配。打开仓库、切统计页、正常核实动作，不需要单独写长篇决策。

点击前：状态引用、经验版本、候选取舍、选择、代价、未知、可检验预测；用 tools/rsi.py prepare 保存后执行。

执行中：只记结果与状态差异。余额或布局不符时，停止依赖它的动作；新的重要决定另存点击前记录。

结果后：用 finish 集中回填支持 / 反驳 / 未知。每日快照一次，经验有新证据再修订，终局 build / check。

怎么证明快了，而不是只是觉得快

基线：第9天已有before/after和截图，包含分散读取、装配重试与模型往返；也含首领、用户讨论和工具中断，不能把整段墙钟时间当普通一天速度。截图数量不能反推出模型耗时。

假设：阶段信息齐备后集中判断，复用说明和购物记忆，可减少模型往返，同时不降低战前记录覆盖率、不增加漏检。
